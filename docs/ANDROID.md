# Android export and release checklist

The game uses a 480×270 logical layout rendered at window resolution, with a fixed 16:9 landscape aspect ratio. Godot 4.6.2 is pinned in CI. Android presets use generated Gradle builds targeting API 36; generated files and signing material remain excluded from Git.

1. Install Godot 4.6.2 and its matching **Android export templates**.
2. Configure the Android SDK and JDK 17 in Editor Settings. Install SDK platforms 35 and 36 and build tools 35.0.1 and 36.0.0. The engine's Gradle template compiles with 35 while the export target override is 36; verify the produced manifest, rather than assuming the template default is the release target.
3. Use the checked-in Android Debug or Android Release preset, using the new package ID `com.tripperdeelabs.motothrash`. Install the Android build template through the editor or `--install-android-build-template` alongside the export command.
4. Generate a debug APK, install on a physical Android device, and check touch behavior, both landscape directions, edge cutouts, framerate, and suspend/resume.
5. The project includes an original SVG launcher icon and synthesized sound effects. Prepare final adaptive icon artwork and store screenshots; inspect launcher masking on actual devices.
6. Before release, test each track and the unlock/save system; verify no stuck boost after interruptions and no loss of progress.
7. Configure your **own** upload keystore using secrets outside GitHub, then export the Android Release preset to `build/moto-thrash-release.aab`. Use `python3 tools/build_android_release.py --sign` with the local MOTO_UPLOAD_KEYSTORE, MOTO_UPLOAD_ALIAS and MOTO_UPLOAD_PASSWORD environment variables. No upload key is configured or generated by this audit. Omit `--sign` for a clearly labeled unsigned validation bundle. Validate the resulting signed bundle and install APKs generated from that bundle before uploading.
8. On Google Play, select a **paid app** with a $0.99 price where supported. Pricing and availability vary by country/tax; a paid app cannot be converted to free and back freely in all store flows.

No ad, analytics, or third-party network SDK exists in the game source. Sound is implemented; haptics are not. Inspect the final release manifest and dependencies before completing the Data safety declaration.

## Gameplay audit — October 8, 2026

The accelerated campaign check runs the actual race physics, countdown, terrain, boost control, finish, and next-course flow across all 24 tracks. Separate tests cover touch input, custom-course persistence, terrain contact/crashes, surface effects, audio generation, and sprite loading. These are automated checks, not a substitute for human playtesting or phone performance measurements.

The earlier pre-hazard campaign baseline was 24/24 finishes, 12 wins, 22 podium finishes and zero demo-rider crashes. After adding jump hazards, all 24 courses again completed without demo-rider crashes or stuck races. Treat these as automated baselines; the new obstacles, balance tricks and Stunt Show need human difficulty testing on phones.

Additional checks cover all six hazard types (ramp clearance, landing inside hazards, safe adjacent lanes and rival penalties), both analog wheelie directions and loss of balance, and Stunt Show. The HIGH/MAX configuration clears 20 buses with a clean landing; an underpowered configuration fails and cannot overwrite the best score. Stunt scores persist separately from campaign records. The builder now uses two tool pages, and changed campaign courses retain their old records in legacy save sections rather than comparing incompatible layouts.

Browser checks exercised all six hazard tools, their automatic ramps, a CPU custom ride, both wheelie gestures and release, and a completed 20-bus Stunt Show jump. The 20-bus baseline scored 2170 with a jump distance of 1703 game units. The Stunt Show camera uses an overview with the runway above the touch controls; verify readability and steering precision on physical phones before release.

The local `build/moto-thrash-debug.apk` was exported with Godot 4.6.2, targets API 36, includes arm64 native libraries, and passes `apksigner verify` and `zipalign -c -P 16 4`. Both native libraries have ELF LOAD alignment of 0x4000. This is debug-signed test output, not an upload-signed release AAB, and 16 KB runtime behavior remains untested.

Fixed during this pass:

- Boost now has pulsing READY, animated ACTIVE, cooling progress, and a disabled WAIT state.
- Android Back pauses/resumes a race and returns from results or the builder. Backgrounding clears held touch controls.
- Results have a touch-accessible Back button and show finishing place.
- Finish records use the line-crossing time rather than a whole extra physics frame.
- Editing, clearing, or undoing a custom course invalidates its old best time.
- Rivals use heat-limited boost cycles, replacing the late-game permanently elevated pace.
- CI now runs every gameplay test rather than only the two original tests.

## Remaining release gates

- Physical phones: both landscape directions, cutouts, multitouch, app switching, interruptions, audio routing, battery/thermal load, low-end framerate, cold launch, save/relaunch, and installation/update from the final signed bundle. No physical Android device was attached during this audit.
- Human difficulty testing: confirm that beginners understand lean/landing and heat management; tune medal thresholds and rival pacing from actual players. The demo completing a track does not establish that the difficulty is fun.
- Signed AAB: configure upload signing, verify API 36 in the output, run bundle validation and Play pre-launch reports, and test native libraries on a 16 KB page-size environment. A debug APK is not a store submission artifact.
- Store setup: final name/art review, screenshots, feature graphic, support contact (feedback@tripperdeelabs.com), privacy policy (https://tripperdeelabs.com/moto-thrash/privacy/), accurate Data safety/content rating/target audience declarations, paid-app pricing, and country availability.
- Where applicable, complete the personal-account closed test with at least 12 opted-in testers for 14 consecutive days before requesting production access.

Requirements checked against [Google Play target API requirements](https://developer.android.com/google/play/requirements/target-sdk), [16 KB page-size guidance](https://developer.android.com/guide/practices/page-sizes), [personal-account testing requirements](https://support.google.com/googleplay/android-developer/answer/14151465), and [Godot Android export documentation](https://docs.godotengine.org/en/stable/tutorials/export/exporting_for_android.html). Confirm the final bundle against the requirements shown in your Play Console at submission time.
